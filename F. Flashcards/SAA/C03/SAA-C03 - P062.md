#Q
*A CRM application is facing user experience issues with users reporting frequent sign-in requests from the application. The application is currently hosted on multiple EC2 instances behind an Application Load Balancer. The engineering team has identified the root cause as unhealthy servers causing session data to be lost. The team would like to implement a distributed in-memory cache-based session management solution. As a solutions architect, which of the following solutions would you recommend?*
1. Use Elasticache for distributed cache-based session management
2. Use DynamoDB for distributed in-memory cache-based session management
3. Use Application Load Balancer sticky sessions
4. Use RDS for distributed in-memory cache-based session management
?
**Answer:**
Use [[Amazon ElastiCache]] for distributed cache-based session management

**Explanation:**
Elasticache is an Amazon Web Services (AWS) service specifically designed for distributed cache-based session management. It provides an in-memory caching solution that can help improve the performance and scalability of the application by storing session data in memory, reducing the load on the backend servers.
