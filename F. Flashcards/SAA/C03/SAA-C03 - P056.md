#Q
*A silicon valley based startup has a two-tier architecture using EC2 instances for its flagship application. The web servers (listening on port 443), which have been assigned security group A, are in public subnets across two Availability Zones and the MSSQL based database instances (listening on port 1433), which have been assigned security group B, are in two private subnets across two Availability Zones. The DevOps team wants to review the security configurations of the application architecture. As a solutions architect, which of the following options would you select as the MOST secure configuration? (Select two)*
1. For security group A: Add an inbound rule that allows traffic from all sources on port 443. Add an outbound rule with the destination as security group B on port 443
2. For security group B: Add an inbound rule that allows traffic only from all sources on port 1433
3. For security group A: Add an inbound rule that allows traffic from all sources on port 443. Add an outbound
4. For security group B: Add an inbound rule that allows traffic only from security group A on port 1433
?
**Answer:**
5. For security group A: Add an inbound rule that allows traffic from all sources on port 443. Add an outbound rule with the destination as security group B on port 443
6. For security group B: Add an inbound rule that allows traffic only from security group A on port 1433

**Explanation:**
Inbound traffic from all sources on port 443, which is typically used for HTTPS. While it may be necessary for the web servers to accept incoming traffic on port 443, it is not the most secure approach to allow traffic from all sources. Limiting the traffic to specific trusted sources would be more secure.  
  
On the other hand, allows inbound traffic from security group A on port 1433. This is a more secure approach as it restricts the traffic to the specific security group that contains the web servers. By allowing traffic only from trusted sources, the potential attack surface is reduced.
