#Q
*Which account strategy would be most suitable for maximizing security and operational efficiency for an oil and gas utility company, organized into multiple autonomous departments, that needs to create a Cloud governance scheme for their AWS resources used in projects reviewed by regulatory boards for customer price increases?*
1. Create an Organizational Unit structure in AWS Organizations with separate underlying accounts for production, development, and testing environments
2. Create multiple AWS accounts, one for each autonomous department within the company
3. Create multiple AWS accounts: one for the production environment, one for the development environment, and one for the testing environment for all departments
4. Create a single AWS account for centralized security management
?
**Answer:**
Create an Organizational Unit structure in [[AWS Organizations]] with separate underlying accounts for production, development, and testing environments

**Explanation:**
In this scenario, creating an Organizational Unit (OU) structure in AWS Organizations with separate underlying accounts for production, development, and testing environments would be the most appropriate strategy. This approach allows for better isolation, governance, and security of resources. Each department can have its own AWS account within the OU structure, providing autonomy and control over their resources. The OU structure enables centralized management and control over the accounts, ensuring compliance with regulations. It also allows for fine-grained access control and the ability to set different security policies for each account. This strategy offers a balance between security, operational efficiency, and regulatory compliance for the company.
