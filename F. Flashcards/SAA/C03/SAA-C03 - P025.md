#Q
*A company has an Amazon EC2 instance running on a private subnet that needs to access a public websites to download patches and updates. The company does not want external websites to see the EC2 instance IP address or initiate connection to it. How can a solution architect achieve this objective? (One option)*
1. Create a security group that only allows connections from the IP address range of the public website. Attach the security group to the EC2 instance.
2. Create a NAT gateway in a public subnet. Route outbound traffic from the private subnet through the NAI gateway
3. Create a network ACL for the private subnet where the EC2 instance deployed only allows access from the IP address range of the public website.
4. Create a site-to-site VPN connection between the private subnet and the network in which the public site is deployed.
?
**Answer:**
Create a NAT gateway in a public subnet. Route outbound traffic from the private subnet through the NAI gateway

**Explanation:**
By creating a NAT gateway in a public subnet and routing outbound traffic from the private subnet through it, the EC2 instance's requests to external websites will appear to originate from the NAT gateway's IP address rather than the EC2 instance's IP address. This effectively hides the instance's IP address from the external websites.
