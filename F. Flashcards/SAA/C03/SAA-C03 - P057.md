#Q
*A social photo-sharing company is storing user profile pictures in an S3 bucket and an image analysis application is deployed on four EC2 instances. A solutions architect would like to trigger an image analysis procedure only on one of the four EC2 instances for each photo uploaded. What do you recommend?*
1. Create an S3 Event Notification that sends a message to an SNS topic. Subscribe the EC2 instances to the SNS topic
2. Create an S3 Event Notification that sends a message to an SQS queue. Make the EC2 instances read from the SQS queue
3. Create a CloudWatch Event that reacts to objects uploads in S3 and invokes one of the EC2 instances
4. Subscribe the EC2 instances to the S3 Inventory stream
?
**Answer:**
Create an S3 Event Notification that sends a message to an [[Amazon Simple Queue Service (Amazon SQS)]] queue. Make the [[Amazon EC2]] instances read from the SQS queue

**Explanation:**
When a new photo is uploaded to S3, the S3 Event Notification can trigger an event that sends a message to an Amazon Simple Queue Service (SQS) queue. Each of the EC2 instances could then poll the SQS queue for new messages (each representing a new photo to be processed). This approach ensures that only one EC2 instance processes each photo, because once an instance retrieves a message from the queue, that message is temporarily hidden from the other instances (to prevent duplicate processing).
