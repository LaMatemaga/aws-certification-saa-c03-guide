#Q
*A media company has documents, videos, images and other paid content that is currently hosted in their own datacenter. Content is personalized based on signed-on user. Users are located world wide and they are complaining about timeouts and poor performance. What options do you have to address this situation? (Select two)*
1. Store media files and other static content in S3. Use Amazon CloudFront to cache at the edge location. Dynamic and personalized content is not supported by CludFront
2. Store media files and other static content in S3. Use Amazon CloudFront to handle all your application request (including personalized content)
3. Use Elastic Cache to cache contents at edge location
4. Migrate application to AWS and deploy across multiple regions. Use Route53 latency based routing to direct customers to appropriate region
?
**Answer:**
5. Store media files and other static content in [[Amazon S3]]. Use [[Amazon CloudFront]] to handle all your application request (including personalized content)
6. Migrate application to AWS and deploy across multiple regions. Use [[Amazon Route 53]] latency based routing to direct customers to appropriate region

**Explanation:**
**Store media files and other static content in S3. Use Amazon CloudFront to handle all your application request (including personalised content)**
This option allows you to use [[Amazon S3]], a highly scalable, reliable, and low-latency data storage infrastructure, to store your media files and other static content. [[Amazon CloudFront]], a content delivery network (CDN), can then be used to distribute this content to your users globally. CloudFront can handle all your application requests, including personalized content, reducing latency and improving the user experience.

**Migrate application to AWS and deploy across multiple regions. Use Route53 latency based routing to direct customers to appropriate region**
By migrating your application to AWS and deploying it across multiple regions, you can further reduce latency for your users worldwide. AWS's global infrastructure means you can host your application closer to your user base, thus reducing the distance data has to travel and the associated latency. [[Amazon Route 53]], a scalable and highly available Domain Name System (DNS) web service, can then be used to route users to the nearest endpoint based on latency, further improving performance.
